अब तक, जब आपने फंक्शन बनाए हैं, तो हर फंक्शन ने अपने आप काम किया है और उसमें वह सारा लॉजिक मौजूद रहा है जो उसे काम करने के लिए चाहिए।

अब हम देखेंगे कि फंक्शन को इस तरह छोटे-छोटे टुकड़ों में कैसे बाँटा जाए कि हमारे पास छोटे फंक्शन हों जो एक-दूसरे के साथ काम करें, बजाय बड़े फंक्शन के जिनमें बहुत कुछ चल रहा हो।

प्रोग्रामिंग में एक सामान्य नियम है कि हर फंक्शन से कम से कम काम करवाना चाहिए। इसे हम फंक्शन की एक ज़िम्मेदारी (_single responsibility_) कहते हैं। हर फंक्शन को बस एक काम करना चाहिए और बाकी छोटे हिस्सों के लिए दूसरे फंक्शन का इस्तेमाल करना चाहिए।

तो चलिए एक उदाहरण देखते हैं।

कल्पना कीजिए कि हमारे पास एक फंक्शन है जिसका काम एक ऐसी स्ट्रिंग लौटाना है जो किसी नाम के बारे में बताए।

इसका एक सरल रूप कुछ ऐसा होगा। इसमें एक गिनती करने वाला लूप है, जैसा आपने पहले भी लिखा है, और उसके बाद एक स्ट्रिंग टेम्पलेट है जो नतीजे को जोड़कर तैयार करता है।

```javascript
function describeName(name) {
  let length = 0
  for (const letter in name) {
    length += 1
  }
  return `This name is ${length} letters long`
}
```

यह ठीक काम करता है, लेकिन यह दो काम कर रहा है। एक काफी सामान्य काम, गिनती करना, और दूसरा बहुत विशेष काम, इस स्ट्रिंग को एक खास फॉर्मेट में तैयार करना।

इसे दो फंक्शन में बाँट देना कहीं बेहतर होगा — एक जिसकी ज़िम्मेदारी गिनती करना हो और दूसरा जो इस विशेष फॉर्मेट में नाम के बारे में बताए।

```javascript
// बस अक्षर गिनता है
function countLetters(str) {
  let count = 0
  for (const letter in str) {
    count += 1
  }
  return count
}

// बस टेक्स्ट को अच्छी तरह फॉर्मेट करता है
function describeName(name) {
  const count = countLetters(name)
  return `The name has ${count} letters`
}
```

और फिर हम इस सामान्य गिनती वाले फंक्शन का दोबारा इस्तेमाल इस स्ट्रिंग फॉर्मेटिंग में ही नहीं, बल्कि किसी भी दूसरी जगह कर सकते हैं जहाँ ज़रूरत हो। जब भी हमें किसी स्ट्रिंग के अक्षर गिनने हों, तो यह प्रिंटिंग वाली चीज़ से पूरी तरह अलग है।

आप दोनों फंक्शन को अलग-अलग पढ़कर तुरंत समझ सकते हैं कि हर एक क्या करता है।

जैसे-जैसे आपके फंक्शन ज़्यादा जटिल होते जाएँगे और आपके पास उनकी संख्या बढ़ेगी, यह तकनीक साफ़ और पढ़ने में आसान कोड और पूरी तरह अव्यवस्था व गड़बड़ के बीच का फ़र्क पैदा करती है।

यहाँ एक बात फिर से बताने लायक है, और वह यह कि आप किसी फंक्शन के अंदर जो कुछ भी बनाते हैं, उसे दूसरे फंक्शन तब तक नहीं देख सकते जब तक आप जानबूझकर उसे लौटा न दें।

इसलिए अगर आप `count` (गिनती) वेरिएबल को `describeName` (नाम के बारे में बताने वाला) के अंदर से इस्तेमाल करने की कोशिश करें, तो आप ऐसा नहीं कर सकते, क्योंकि वह दूसरे फंक्शन का है।

JavaScript में हम सबसे ऊपर ऐसे वेरिएबल बना सकते हैं जो सभी फंक्शन के बीच शेयर होते हैं, लेकिन मैं सलाह देता हूँ कि आप ऐसा न करें, जब तक कि कोई बहुत अच्छी वजह न हो।

जितना ज़्यादा आप हर फंक्शन को स्वतंत्र रखेंगे, और इसे तकनीकी भाषा में प्योर फंक्शन (_pure function_) कहते हैं, उतना ही आपका कोड साफ़ होगा और उतनी ही कम बग आप बनाएँगे।
