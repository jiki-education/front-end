تا به حال، وقتی تابع می‌نوشتید، هر تابع تقریباً به‌تنهایی کار می‌کرد و همهٔ منطق لازم برای کار را در خود جای می‌داد.

حالا می‌خواهیم ببینیم چطور توابع را به بخش‌های کوچک‌تر تقسیم کنیم تا به جای توابع بزرگ و شلوغ، توابع کوچکی داشته باشیم که با هم کار می‌کنند.

در برنامه‌نویسی، یک قاعدهٔ کلی این است که هر تابع باید حداقل کار ممکن را انجام دهد. به این می‌گوییم تابعی که «تک‌مسئولیتی» است. هر تابع فقط باید یک کار انجام دهد و برای بخش‌های فرعی آن کار از توابع دیگر استفاده کند.

خب، بیایید به یک مثال نگاه کنیم.

تصور کنید تابعی داریم که کارش برگرداندن رشته‌ای است که یک اسم را توصیف می‌کند.

یک نسخهٔ ساده‌اش شبیه این خواهد بود. یک حلقهٔ شمارش داریم، چیزی که شما قبلاً آن را نوشته‌اید، و بعد یک الگوی رشته که نتیجه را کنار هم می‌چیند.

```javascript
function describeName(name) {
  let length = 0
  for (const letter in name) {
    length += 1
  }
  return `This name is ${length} letters long`
}
```

این به‌خوبی کار می‌کند، اما در حال انجام دو کار است. یک کار نسبتاً عمومی، یعنی شمردن، و یک کار دیگر بسیار خاص، یعنی ساختن این رشته با یک قالب مشخص.

خیلی بهتر است این را به دو تابع تقسیم کنیم: یکی که وظیفه‌اش شمردن باشد و دیگری که وظیفه‌اش توصیف یک اسم با این قالب مشخص باشد.

```javascript
// فقط حروف را می‌شمرد
function countLetters(str) {
  let count = 0
  for (const letter in str) {
    count += 1
  }
  return count
}

// فقط متن را به‌خوبی قالب‌بندی می‌کند
function describeName(name) {
  const count = countLetters(name)
  return `The name has ${count} letters`
}
```

و بعد می‌توانیم از آن تابع عمومی شمارش هم در این قالب‌بندی رشته و هم در هر جای دیگری که نیاز داریم، دوباره استفاده کنیم. هروقت نیاز به شمردن حروف یک رشته داشته باشیم، این تابع کاملاً مستقل از هرچیز مربوط به چاپ کردن است.

می‌توانید هر دو تابع را جداگانه بخوانید و فوراً بفهمید هرکدام چه کاری انجام می‌دهد.

با پیچیده‌تر شدن توابع و بیشتر شدن تعدادشان، این تکنیک تفاوت بین داشتن کد منظم و خوانا و آشفتگی و به‌هم‌ریختگی کامل است.

یک نکته هست که ارزش دارد دوباره اینجا به آن اشاره کنیم و آن این است که هر چیزی که درون یک تابع می‌سازید، توسط توابع دیگر قابل دسترسی نیست، مگر اینکه عمداً آن را برگردانید.

پس اگر سعی کنید به متغیر `count` (تعداد) از درون `describeName` (توصیف نام) ارجاع دهید، نمی‌توانید، چون متعلق به تابع دیگر است.

در JavaScript، می‌توانیم متغیرهایی را در بالاترین سطح، بالای همه‌چیز، تعریف کنیم که بین توابع به اشتراک گذاشته شوند، اما قویاً توصیه می‌کنم این کار را نکنید، مگر اینکه دلیل خیلی خوبی وجود داشته باشد.

هرچه بیشتر هر تابع را مستقل نگه دارید — و کلمهٔ تخصصی آن «خالص» است، توابع خالص — کدتان تمیزتر می‌شود و bugهای کمتری ایجاد می‌کنید.
