Досі, коли ми писали функції, кожна з них здебільшого була цілком самостійною й містила всю логіку, потрібну їй для роботи.

Тепер розглянемо, як розбивати функції на менші, що працюють разом, замість великих функцій, у яких відбувається багато всього одразу.

Загальне правило в програмуванні: кожна функція має робити якомога менше. Це називається єдиною відповідальністю (англ. _single responsibility_) функції. Кожна функція повинна робити лише одну річ і використовувати інші функції для окремих частин цієї роботи.

Тож розгляньмо приклад.

Уявімо, що в нас є функція, яка має повертати рядок тексту (англ. _string_) з описом імені.

Проста версія виглядала б так. Тут є цикл, який рахує (такі ми вже писали), а потім шаблонний рядок, який складає результат докупи.

```javascript
function describeName(name) {
  let length = 0
  for (const letter in name) {
    length += 1
  }
  return `This name is ${length} letters long`
}
```

Це чудово працює, але функція робить дві речі. Одну доволі загальну, підрахунок, і одну дуже конкретну: вона певним чином задає вигляд (або формат) цього рядку тексту.

Було б набагато краще розбити це на дві функції: одна відповідає за підрахунок, а інша описує імʼя в цьому конкретному форматі.

```javascript
// Просто рахує літери
function countLetters(str) {
  let count = 0
  for (const letter in str) {
    count += 1
  }
  return count
}

// Просто гарно форматує текст
function describeName(name) {
  const count = countLetters(name)
  return `The name has ${count} letters`
}
```

І тоді ми можемо повторно використати цю загальну функцію підрахунку і у форматуванні цього рядка тексту, і в будь-якому іншому місці, де вона нам знадобиться. Щоразу, коли потрібно порахувати літери в рядку тексту, цей підрахунок повністю відокремлений від усього, що стосується виведення тексту на екран.

Кожну з цих функцій можна прочитати окремо й одразу зрозуміти, що вона робить.

Коли функції стають складнішими та їх стає більше, саме цей підхід відділяє акуратний, читабельний код від цілковитої плутанини й безладу.

Тут варто ще раз згадати одну річ: усе, що ми створюємо всередині функції, недоступне іншим функціям, якщо ми свідомо не повернемо ці значення з функції.

Тож якщо ми спробуємо звернутися до змінної `count` (кількість) зсередини `describeName` (описати імʼя), нічого не вийде, адже вона належить іншій функції.

У JavaScript можна створювати змінні на початку документа, над усім іншим кодом, і вони будуть спільними для всіх функцій, але я щиро раджу цього не робити, якщо на це немає дуже вагомої причини.

Чим більш незалежними ми робимо наші функції, а для таких функцій є технічний термін: чисті (англ. _pure_) функції, тим чистішим буде наш код і тим менше помилок (багів) ми в ньому створимо.
