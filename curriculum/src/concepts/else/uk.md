Умовні конструкції дають нам змогу перевіряти умови і виконувати код лише тоді, коли щось є правдивим. А тепер познайоммося з вірним напарником `if`: ключовим словом `else`.

Коли Jiki бачить умовну конструкцію (англ. _if statement_), він виконує блок коду, якщо умова правдива, і пропускає цей блок, якщо вона неправдива. Але що робити, якщо ми хочемо, щоб Jiki зробив одне, коли умова правдива, і щось інше, коли вона неправдива? Саме для цього існує `else`. Ми можемо додати гілку `else` (англ. _else clause_) після закривальної фігурної дужки `if`, і Jiki виконає її, якщо умова в `if` неправдива. Повернімося до прикладу з охоронцем клубу: тепер ми можемо або відчинити двері, або відмовити людині, і це, мабуть, краще, ніж повністю ігнорувати її, як ми робили раніше. Уявімо це як розвилку на дорозі. Jiki доходить до розвилки, перевіряє умову й далі йде одним шляхом, якщо вона правдива, або іншим, якщо неправдива. Але він ніколи не йде обома шляхами одночасно.

```javascript
if (age >= 21) {
  openDoor()
} else {
  turnAway()
}
```

А якщо можливих варіантів більше ніж два? Уявімо, що наш охоронець продає квитки. Кому менше тринадцяти, той отримує дитячий квиток. Кому від тринадцяти до двадцяти, тому дістається підлітковий квиток. А кому двадцять або більше, той отримує квиток для дорослих. Отже, тепер маємо три різні результати. Для цього ми можемо додати ще одну умовну конструкцію після `else`. Тобто сказати: «Якщо це, зроби це. Інакше, якщо це, зроби те. Інакше зроби щось третє». У цьому прикладі Jiki побачить `if` і перевірить першу умову. Шістнадцять менше за тринадцять? Ні. Тож він переходить до `else if`. Шістнадцять менше за двадцять? Так, це правда. Тож він виконує цей блок і видає підлітковий квиток. І на цьому все. Він більше нічого не перевіряє. Він узагалі не дивиться на останній `else`. Щойно Jiki знаходить правдиву умову, він виконує її блок і пропускає все, що нижче.

```javascript
if (age < 13) {
  childTicket()
} else if (age < 20) {
  teenTicket()
} else {
  adultTicket()
}
```

Це найголовніше, що тут треба зрозуміти. Завжди виконується лише один блок. Jiki проходить цим ланцюжком умов згори донизу, знаходить першу правдиву умову, виконує її блок і рухається далі.

І ще одна річ, яку варто добре засвоїти, бо на ній часто спотикаються. Між двома окремими умовними конструкціями та `else if` є тонка, але дуже важлива різниця. Уявімо, що ми пишемо програму, яка видає звичайний приз або бонусний приз залежно від кількості очок. Погляньмо на два варіанти. Перший варіант використовує `else if`, а другий використовує дві окремі конструкції `if`. Що відбуватиметься по-різному?

```javascript
if (score > 100) {
  bonusPrize()
} else if (score > 50) {
  basicPrize()
}
```

```javascript
if (score > 100) {
  bonusPrize()
}
if (score > 50) {
  basicPrize()
}
```

У першому випадку, з `else if`, ми перевіряємо, чи набрано достатню кількість очок, і видаємо приз, а далі `else if` уже не виконується. Тож людина, яка набрала понад сто очок, отримує лише бонусний приз.

А в другому прикладі дві конструкції `if` повністю незалежні одна від одної. Виконаються обидві, і обидві умови будуть правдивими. Тож тут людина отримує два призи. У першому варіанті приз лише один. У другому їх два. Зупиніться на хвилину й переконайтеся, що справді це зрозуміли.

Цікаво також, що правильним може бути будь-який із варіантів, залежно від задуму гри. Можливо, учасник має отримати і звичайний приз, і бонусний, а можливо, його просто підвищують до бонусного призу. Жоден із цих фрагментів коду не є правильним чи неправильним сам по собі. Вони просто корисні в різних ситуаціях. Але нам треба чітко розуміти, який саме варіант ми збираємося використати.
