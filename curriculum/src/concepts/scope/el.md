Φαντάσου κώδικα που σχεδιάζει έναν κύκλο σε διαφορετικό σημείο κάθε φορά που εκτελείται, και θέλουμε να σχεδιάσουμε 10 κύκλους σε διαφορετικά σημεία. Θα μπορούσαμε να το συνδυάσουμε με έναν βρόχο. Αλλά για όσους από εσάς προσέχετε πραγματικά, μπορεί να παρατηρήσατε κάτι περίεργο εδώ.

```javascript
repeat(10) {
  let left = Math.randomInt(0, 100)
  let top = Math.randomInt(0, 100)
  circle(left, top, 5, "blue")
}
```

Νωρίτερα, είπα ότι υπάρχει ένας κανόνας ότι τα κουτιά στα ράφια του Jiki πρέπει να έχουν μοναδικά ονόματα,

και ότι η λέξη-κλειδί `let` δημιουργεί ένα νέο κουτί κάθε φορά που τη χρησιμοποιείς.

Αλλά επειδή η `let` βρίσκεται μέσα σε έναν βρόχο, ο Jiki θα δημιουργεί ένα νέο κουτί κάθε φορά που εκτελείται ο βρόχος.

Επομένως, είναι λάθος ο κώδικας, ή συμβαίνει κάτι άλλο παράξενο εδώ;

Λοιπόν, αποδεικνύεται ότι ο κώδικας είναι μια χαρά. Αυτό είναι απολύτως έγκυρη JavaScript, και λειτουργεί χάρη σε μια έννοια που ονομάζεται εμβέλεια (_scope_ στα αγγλικά), ή απλώς εμβέλεια.

Η εμβέλεια είναι κάτι που αρχικά μάλλον θα σου φανεί αρκετά απλό, αλλά μπορώ να σου εγγυηθώ ότι θα σου προκαλέσει πόνο για την υπόλοιπη καριέρα σου. Ακόμα και οι πιο έμπειροι προγραμματιστές αντιμετωπίζουν προβλήματα με την εμβέλεια, και η JavaScript είναι μία από τις πιο περίπλοκες γλώσσες για αυτό. Σου το λέω αυτό για να μην αισθανθείς άσχημα όταν αντιμετωπίσεις προβλήματα με την εμβέλεια. Αλλά επίσης, πρόσεξε πραγματικά αυτό το κομμάτι γιατί είναι σημαντικό.

Όταν βλέπεις ένα άγκιστρο στον κώδικα, δημιουργεί αυτό που ονομάζεται νέα εμβέλεια. Τι σημαίνει αυτό; Λοιπόν, μπορείς να φανταστείς ότι ο Jiki δημιουργεί ένα νέο μικρό σετ ράφια στο εργαστήριό του κάθε φορά που βλέπει ένα άγκιστρο. Και όσα κουτιά δημιουργεί ενώ δουλεύει, εκτελώντας κώδικα μέσα σε αυτά τα άγκιστρα, αυτά τα κουτιά, αυτά τα νέα κουτιά πηγαίνουν στο μικρό νέο σετ ράφια, όχι στα κύρια.

Έτσι, κάθε φορά που έχουμε έναν βρόχο σαν αυτόν, μπορούμε να δημιουργούμε κουτιά που διαρκούν μόνο όσο διαρκεί κάθε εκτέλεση του βρόχου. Τα κουτιά `left` (αριστερά) και `top` (πάνω) που βλέπεις εδώ διαρκούν μόνο μέχρι να φτάσουμε στο κλειστό άγκιστρο, και μετά πετιούνται. Και ο Jiki φτάνει σε αυτό το κλειστό άγκιστρο κάθε φορά που εκτελείται ο βρόχος. Άρα είναι 10 φορές σε αυτό το πρόγραμμα. Άρα 10 φορές θα δημιουργήσει ένα κουτί με το όνομα `left`, και θα το πετάξει ξανά.

Έτσι, όταν δημιουργείς μια μεταβλητή, πρέπει να αποφασίζεις για πόσο χρόνο θέλεις να παραμείνει. Αν θέλεις να ζήσει για πολύ καιρό, πρέπει να βρίσκεται έξω από οποιαδήποτε άγκιστρα. Αν θέλεις να διαρκέσει μόνο για μία επανάληψη (_iteration_ στα αγγλικά), μία διάρκεια του βρόχου, τότε μπορείς να τη βάλεις μέσα στα άγκιστρα. Βλέπεις πώς όλο αυτό μπορεί να μπερδέψει λίγο; Ένας καλός κανόνας για να το κρατάς απλό όταν ξεκινάς είναι να κρατάς όλες τις μεταβλητές σου κοντά στην κορυφή του κώδικα έξω από τα άγκιστρα, και μετά μόνο να τις ενημερώνεις μέσα στα άγκιστρα. Για παράδειγμα, θα μπορούσαμε να γράψουμε τον παραπάνω κώδικα με ένα μόνο κουτί `left` και `top` που να έχει την τιμή μηδέν στην αρχή και να ενημερώνεται κάθε φορά μέσα στον βρόχο. Και αυτό είναι απολύτως έγκυρο. Κανένα από τα δύο δεν είναι σωστό ή λάθος. Υπάρχουν βέλτιστες πρακτικές, αλλά θα μάθουμε γι' αυτές αργότερα. Για την ώρα, πειραματίσου, διασκέδασε, δες τι σου φαίνεται πιο άνετο, και προσπάθησε να μην ανησυχείς πολύ γι' αυτό.
